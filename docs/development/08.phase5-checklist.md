## 5. 성능 측정 — TC-050 (NFR-004)

**기대 결과:** 정적 화면 LCP¹ 2.5초 이하, 대시보드 API(캐시 적중) 1초 이하.

¹ LCP(Largest Contentful Paint): 화면의 가장 큰 내용이 그려지기까지 걸린 시간

**방법 (PC 크롬)**

1. 포털에 로그인한 상태에서 측정할 화면을 연다
2. `F12` → 상단 **Lighthouse** 탭 (없으면 `»` 안에 있음)
3. Mode: Navigation / Device: **Mobile** / Categories: **Performance**만 체크 → **Analyze page load**
4. 결과의 **Largest Contentful Paint** 값을 적는다
5. API 응답 시간: `F12` → **Network** 탭 → 대시보드 새로고침 → `programs` 요청의 Time 값 (두 번째 새로고침 값 = 캐시 적중)

| 화면 | LCP (≤ 2.5초) | 결과 |
|---|---|---|
| `/program/overview` |  |  |
| `/coaching/career/2` |  |  |
| `/records/journal` |  |  |
| `/dashboard` |  |  |
| `/api/programs` 응답 (두 번째, ≤ 1초) |  |  |

> Lighthouse가 비밀번호 때문에 측정을 못 하면 로그인한 같은 탭에서 다시 실행한다.

**사전 로컬 측정 (2026-10-19, Claude — 운영 아님, 참고용)**

같은 빌드를 로컬 `next start`로 띄워 Lighthouse 12.8(Mobile, 모의 4G)로 측정했다. 첫 측정에서 모든 화면의 LCP가 약 12초로 기준을 크게 넘었다. 원인은 한글 폰트 통짜 파일(2MB)이었고, 글자 범위별로 나뉜 파일(dynamic subset)로 바꿔 화면에 쓰인 글자 묶음만(약 260~360KB) 내려받게 했다.

| 화면 | 변경 전 LCP | 변경 후 LCP | 성능 점수 (후) |
|---|---|---|---|
| `/program/overview` | 12.2초 | **2.2초** | 97 |
| `/coaching/career/2` | 12.0초 | **2.0초** | 97 |
| `/records/journal` | 12.1초 | **2.1초** | 98 |
| `/login` (입장 화면) | — | 3.5초 | 81 |
| `/dashboard` | 12.3초 | 3.8초 | 88 |

- 정적 화면 3개는 기준(2.5초 이하) 통과. 운영 배포 후 위 방법으로 **운영에서 다시 측정**해 표에 적는다.
- `/dashboard`는 로컬에 구글 연결이 없어 "설정 미완료" 안내가 늦게 그려진 값이라 운영 값과 다르다. 입장 화면은 폰트 교체 시점이 LCP로 잡혀 기준보다 1초 길다 — 운영 측정 후에도 넘으면 개선한다.

## 9. 운영 전 정리

**왜:** 테스트 데이터가 남아 있으면 실제 대시보드 수치에 섞인다.

> **순서 주의:** 더미 명단·테스트 응답은 UAT(§8)에서 쓰므로 **UAT가 끝난 뒤** 지운다. 서비스 계정 권한 낮추기는 지금 해도 된다 (앱은 읽기만 한다).

- [ ] `roster` 시트: 더미 28행 삭제 (`2026-1-SNU-CAREER` 19행, `2026-1-PARTNER-LIFE` 9행) — 실제 명단으로 교체
- [ ] `programs` 시트: 실제 운영할 프로그램만 남기고 이름·ID·회기 수 최종 확인 (ID는 응답이 쌓인 뒤 바꾸지 않는다)
- [ ] 응답 시트 4개 탭: UAT·테스트로 제출한 응답 행 삭제 (머리글 행은 남긴다)
- [ ] 서비스 계정 권한 낮추기: 응답 시트·참조자료 폴더 공유에서 `scd-coaching-portal@…` **편집자 → 뷰어** (최소 권한)
- [ ] 참조자료 폴더에 개인정보·민감 파일이 없는지 확인 (링크 공개 폴더)
- [ ] 코치 안내문 발송: 포털 주소, 공용 비밀번호(별도 채널로), "카카오톡에서 안 열리면 ⋮ → 다른 브라우저로 열기"
