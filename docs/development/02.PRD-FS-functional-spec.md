## 2. 기능 상세

### FN-001 앱 셸·사이드바

| 항목 | 내용 |
|---|---|
| 목적 | 모든 화면에서 같은 메뉴 구조로 이동하게 한다 |
| 입력 | 현재 주소, 화면 폭, 사이드바 열림 상태 |
| 처리 | ① 화면 폭으로 사이드바 기본 상태 결정 (1024px 이상 펼침, 미만 접힘) ② 현재 주소로 선택 메뉴 강조 ③ 코칭 모델은 현재 유형만 펼침 ④ ☰ 누르면 열림 상태 반전 |
| 출력 | 상단 바(☰, 로고, "삼코동 코칭 포털"), 사이드바 6묶음, 본문 영역 |
| 규칙 | 묶음 순서: 대시보드 → 프로그램 → 코칭 모델 → 일지·소감 → 코치 도구 → 자료 (DEC-011). 선택 메뉴 스타일은 DEC-014 |
| 예외 | 존재하지 않는 주소 → 404 화면(SCR-013), 사이드바는 유지 |
| 데이터 영향 | 없음. 사이드바 열림 상태는 브라우저 저장소에 보관 (실패해도 기본값으로 동작) |
| 완료 기준 | 모든 메뉴가 올바른 화면으로 이동, 키보드로 메뉴 전체 이동 가능 |
| 관련 테스트 | TC-001 ~ TC-006 |

### FN-002 사이트 접근 비밀번호

| 항목 | 내용 |
|---|---|
| 목적 | 앱 주소가 퍼져도 외부인이 운영 정보를 보지 못하게 한다 |
| 입력 | 요청의 `Authorization` 헤더, 환경변수 `SITE_PASSWORD` |
| 처리 | ① 정적 파일 경로는 통과 ② 헤더가 없거나 비밀번호가 다르면 401 + `WWW-Authenticate: Basic` ③ 같으면 통과. 비교는 길이 차이로 정보가 새지 않는 방식(상수 시간 비교)으로 한다 |
| 출력 | 브라우저 기본 비밀번호 창 또는 요청한 화면 |
| 규칙 | 사용자 이름 칸은 아무 값이나 허용하고 비밀번호만 확인한다. 계정·역할 개념 없음 (DEC-007) |
| 예외 | `SITE_PASSWORD`가 설정되지 않은 운영 배포 → 모든 요청 503 + "관리자 설정 필요" (열린 상태로 배포되는 것을 막음) |
| 데이터 영향 | 없음 |
| 완료 기준 | 비밀번호 없이 화면·API 접근 불가 |
| 관련 테스트 | TC-007 ~ TC-010 |

### FN-003 프로그램 개요·워크플로우 그림

| 항목 | 내용 |
|---|---|
| 목적 | 코칭 프로그램이 무엇이고 어떤 순서로 진행되는지, 코치가 앱을 언제 쓰는지 한 화면에서 이해시킨다 |
| 입력 | `content/overview/*.md`, `content/journey.json`, `content/coach-workflow.json` |
| 처리 | ① 개요 본문 표시 (가이드북 1~4장, 1.5 운영 기본 사양) ② 그림 1: 코칭 여정 — journey 단계 순서대로 SVG 도식 생성 ③ 그림 2: 코치 업무 절차 — workflow 단계 순서대로 SVG 생성 ④ 각 그림 아래 같은 내용의 순서 목록 |
| 출력 | 개요 본문, SVG 2개, 단계 목록 2개 |
| 규칙 | 그림의 단계 이름·순서는 데이터 파일과 항상 같다. 단계를 누르면 해당 화면으로 이동 (여정 단계 → 커리어 코칭 해당 회차, 업무 단계 → 관련 메뉴) |
| 예외 | 데이터 파일 형식 오류 → 빌드 실패 (배포 전에 발견) |
| 완료 기준 | 375px에서 그림이 세로 배치로 바뀌고 글자가 잘리지 않음 |
| 관련 테스트 | TC-011 ~ TC-013 |

**그림 1 — 코칭 여정 (가이드북 5.1)**
시작 세션 → 1회기 → Between 1 → 2회기 → Between 2 → 3회기 → Between 3 → 4회기 → Between 4 → 5회기 → Follow-up

**그림 2 — 코치 업무 절차**
① 세션 준비 (회차 가이드 확인) → ② 세션 진행 (질문·추천 도구) → ③ 코칭일지 작성 (구글폼) → ④ Between Session 안내 → ⑤ 마지막 회기 후 종료 리포트 (구글폼) → ⑥ 코치 종료소감 작성 + 피코치 종료소감 링크 전달 → ⑦ 대시보드에서 진행 확인

### FN-004 코칭 모델 회차 가이드·추천 도구

| 항목 | 내용 |
|---|---|
| 목적 | 세션 중 코치가 해당 회차의 목적·질문·산출물을 바로 참조한다 |
| 입력 | 주소의 유형(`career`·`mentoring`·`life`)과 단계(`start`·`1`~`5`·`follow-up`), `content/types/{유형}.json`, `content/tools.json` |
| 처리 | ① 유형·단계 검증 ② 공통 흐름(가이드북 7~16장) + 유형별 내용(17~19장) 결합 ③ 1~4회기는 다음 Between Session 안내를 아래에 붙임 ④ `tools.json`에서 해당 단계 추천 도구를 찾아 표시 |
| 출력 | 회차 제목, 목적, 핵심 질문, 주요 산출물, Between Session 안내, 추천 도구(우선·보조), 이전·다음 회차 이동 |
| 규칙 | 문구는 가이드북 원문 (RULE-007). 멘토링 유형은 SHARE 5단계 카드를 경험 공유 질문 옆에 표시 |
| 예외 | 잘못된 유형·단계 → 404. 추천 도구가 없는 단계 → 추천 도구 영역 숨김 |
| 데이터 영향 | 없음 |
| 완료 기준 | 21개 화면 정상, 도구 추가 시 코드 수정 없이 표시 |
| 관련 테스트 | TC-014 ~ TC-018 |

**`tools.json` 항목 구조**

| 필드 | 예 | 설명 |
|---|---|---|
| `id` | `life-wheel` | 영문 고정 ID |
| `name` | Life Wheel | 가이드북 표기 |
| `purpose` | 삶의 영역별 현재 인식과 우선순위 | 가이드북 27.2 |
| `stages` | `[{"stage":"start","level":"primary"}]` | 추천 단계와 우선(primary)·보조(secondary) 구분 |
| `types` | `["career","mentoring","life"]` | 적용 유형 (비우면 전체) |
| `hubUrl` | 나눔터 주소 또는 도구 상세 주소 | 클릭 시 이동 |

### FN-005 코칭 툴 나눔터 연동

| 항목 | 내용 |
|---|---|
| 목적 | 도구 상세·워크시트를 관리하는 나눔터를 앱 안에서 바로 쓴다 |
| 입력 | 나눔터 주소 (환경 설정 `TOOL_HUB_URL`, 기본값 `https://mkgreeme-web.github.io/CT-Sharing_Hub/`) |
| 처리 | ① 화면 위에 제목·[새 창에서 열기 ↗] 버튼 ② 본문에 iframe으로 나눔터 표시 ③ 일정 시간(8초) 안에 불러오기 완료 신호가 없으면 대체 안내 표시 |
| 출력 | 삽입된 나눔터 또는 대체 안내 + 새 창 버튼 |
| 규칙 | CSP `frame-src`에 나눔터 주소만 허용. iframe에 `title` 지정 |
| 예외 | 나눔터가 삽입을 막는 경우 → 브라우저가 빈 화면을 보여줄 수 있으므로, 시간 초과 시 대체 안내로 전환 (DEC-104 확인 결과에 따라 iframe 제거 가능) |
| 완료 기준 | 정상·삽입 차단 두 경우 모두 새 창 버튼으로 나눔터 접근 가능 |
| 관련 테스트 | TC-019 ~ TC-021 |

### FN-006 일지·소감 구글폼 연계

| 항목 | 내용 |
|---|---|
| 목적 | 정확한 키 값이 채워진 구글폼으로 기록을 남기게 한다 |
| 입력 | `content/forms.json`, 프로그램 목록(API-001), 사용자가 고른 프로그램·고객 코드·회차 |
| 처리 | ① 폼 안내(작성자·시점)와 질의 항목 미리보기 ② 프로그램 선택 → 해당 `roster`의 고객 코드 목록 표시 ③ 코칭일지는 회차 선택 (1 ~ 프로그램 회기 수). 회기 수를 넘는 추가 진행 회차는 "추가 회차"를 골라 번호를 직접 입력 (회기 수+1 ~ 99) ④ 필수 값이 모두 고르면 버튼 활성화 ⑤ prefill 링크 생성: `{폼 주소}?usp=pp_url&entry.{programId 항목}={값}&entry.{clientCode 항목}={값}[&entry.{sessionNo 항목}={값}]` ⑥ 코치용 3종은 새 창 열기, 피코치용은 복사·공유 |
| 출력 | 미리보기, 선택 영역, [구글폼 열기 ↗] 또는 [링크 복사]·[공유] |
| 규칙 | 값은 URL 인코딩. 프로그램이 별도 폼을 쓰면(`programs` 시트의 별도 폼 주소) 그 주소를 사용 (`CLAUDE.md` §5.2). 고객 코드만 쓰고 이름·이메일은 링크에 넣지 않음 (RULE-008) |
| 예외 | 프로그램 목록 조회 실패 → 선택 영역 대신 "목록을 불러오지 못했습니다" + 값 없이 폼 열기 버튼(직접 입력용) 제공. 클립보드 사용 불가 → 링크 텍스트를 선택된 상태로 보여줌 |
| 데이터 영향 | 없음 (링크 생성은 브라우저에서) |
| 완료 기준 | 4종 폼이 올바른 값으로 열림 |
| 관련 테스트 | TC-022 ~ TC-028, TC-057 |

### FN-007 프로그램 현황

| 항목 | 내용 |
|---|---|
| 목적 | 운영 중·예정·종료 프로그램을 한눈에 본다 |

| 처리 | ① 프로그램 목록 조회 ② RULE-005로 형식 검증 ③ 필터 적용 ④ 카드별로 기간, 고객 수, 코칭일지 제출 건수 / 예정 건수 합계, 다음 일정(roster 예정일 중 오늘 이후 가장 가까운 날) 계산 |

| 예외 | 결과 0건 → "조건에 맞는 프로그램이 없습니다" + 필터 초기화 버튼. 조회 실패 → 오류 안내 + 다시 시도 |
| 완료 기준 | 필터 조합 결과가 시트와 일치 |
| 관련 테스트 | TC-029 ~ TC-033 |

### FN-008 프로그램 진행 현황표

| 항목 | 내용 |
|---|---|
| 목적 | 한 프로그램의 고객별 기록 제출 여부를 확인한다 |
| 입력 | 주소의 `programId`, API-002 응답 |
| 처리 | ① 프로그램 존재 확인 ② `roster`의 고객 코드를 행으로 ③ 열: 1~N회차 코칭일지, 종료 리포트, 코치 종료소감, 피코치 종료소감 ④ 응답 시트 4종에서 RULE-004 키로 매칭 ⑤ RULE-009·011·012·013 적용 |
| 출력 | 프로그램 정보, 현황표(칸: 제출 ✓ + 제출일 / 예정 · / 예정일 지남 ○), 안내 문구(명단 외 응답, 작성 순서 확인), 마지막 갱신 시각 |
| 규칙 | 응답 내용 미표시 (RULE-003). 중립 색만 사용 (RULE-001). 열 머리글 정렬 기호 표시 (`DESIGN.md` §4-3) |
| 예외 | 없는 programId → "프로그램을 찾을 수 없습니다" + 목록으로 이동. 명단 0명 → "등록된 참여자가 없습니다" |
| 완료 기준 | 테스트 시트 기준 모든 칸이 정확 |
| 관련 테스트 | TC-034 ~ TC-041 |

**칸 상태 판정**

| 상태 | 조건 | 표시 |
|---|---|---|
| 제출 | 키가 일치하는 응답 1건 이상 | ✓ + 최근 제출일 (primary 계열) |
| 예정일 지남 | 미제출이고 roster 예정일 < 오늘 | ○ (muted) |
| 예정 | 미제출이고 예정일 ≥ 오늘 또는 예정일 없음 | · (muted) |

## 3. 핵심 사용자 흐름

**흐름 A — 세션 준비·진행**
프로그램 개요(처음 1회) → 코칭 모델 › 유형 › 회차 → 질문·추천 도구 확인 → (필요 시) 코칭 툴 나눔터

**흐름 B — 회기 후 기록**
일지·소감 › 코칭일지 → 프로그램·고객 코드·회차 선택 → [구글폼 열기] → 구글폼 작성·제출 → 5분 안에 대시보드 반영

**흐름 C — 과정 종료**
종료 리포트 작성 → 코치 종료소감 작성 → 피코치 종료소감 링크 복사 → 메시지·카카오톡 등으로 고객에게 전달 → 고객이 구글폼 응답

**흐름 D — 운영 모니터링**
프로그램 현황 → 필터 → 프로그램 카드 → 진행 현황표 확인
